Fatal flaws — fix before anything else
UX 4-step wizard to create a plan — students will abandon at step 2
SSC students open this at 11pm under pressure. A wizard with 4 screens before they see any value is dead on arrival. Zero feedback loop during setup — you don't see the plan taking shape until the very end. Fix: collapse to a single smart screen. Show a live preview of the generated schedule in real time as they fill in the date and topics.
UX No preset exam templates for SSC CGL, CHSL, MTS, Railway NTPC etc.
The #1 pain point for Indian students is manually typing out 200+ topics. You're asking them to either type everything from scratch or use a "bulk paste" format they've never seen. The free tier of every competitor already ships with pre-loaded syllabuses. This is table stakes, not a feature.
Code Sequential topic creation — N+1 API waterfall
In createPlanAndSyllabus(), you loop: POST /plans → POST /subjects (sequential) → POST /chapters → POST /topics for every topic. For a 40-topic syllabus that's 40+ sequential network calls. On a 4G mobile connection in a tier-2 city, this is 8–15 seconds of loading. Student closes the tab. Fix: batch endpoint — send entire syllabus as one JSON payload.
UX Zero visual feedback during the 8-15s generation wait
Button changes to "Generating..." — that's it. No progress indicator, no step markers, no estimated time. Students will click it twice, create a duplicate plan, and have no way to recover. You need an animated step-through: "Creating plan → Adding subjects → Distributing schedule → Done"
Product No analytics attached to any user action
You track zero user behaviour. No session logging, no topic completion timestamps, no time-per-topic, no streak tracking, no missed-day detection. The "adaptive planner that understands progress" you want to build has no data foundation to stand on. This is the most important missing piece for the ₹500 ask.
UX Empty state is a dead-end card with one button
When no plan exists, the student sees a white card with "Create your first study plan" and nothing else. No exam countdown, no motivating copy, no social proof, no quick-start options. This is the moment to hook them — and you're showing them a loading screen aesthetic instead.
What's actually good — keep these
Keep Bulk paste parser logic — genuinely clever
The parseBulkPaste() function handles multiple formats (colon, dash, indented bullets) intelligently. This is the seed of a "paste your syllabus PDF text and we'll parse it" feature. Don't remove it — make it more visible and powerful.
Keep Off-days + daily topic goal — right concept
The study capacity model (N topics/day, blocked weekdays) is exactly the right mental model for a realistic SSC planner. Just surface it better — show students the projection: "At 3 topics/day with Sundays off, you'll finish 2 days before exam."
Keep auto-distribute API + lockExistingDates — powerful primitives
Auto-distribution with locked dates is the core of adaptive rescheduling. This is your moat if you build on it. The concept of "reschedule what's left without disturbing what's done" is exactly what the ₹500 ask needs to justify itself.
Keep Section routing — today / plan / syllabus / calendar
Clean URL-based navigation with section normalization. Good architecture for deep-linking. Keep it and extend it — add /analytics and /insights as new route segments.

AI
Smart rescheduling engine (the ₹500 feature)
When a student falls behind, the system calculates exactly how to redistribute the backlog. It accounts for: remaining days, off-days, daily capacity, topic weights (some chapters take longer), and upcoming high-priority subjects. Shows "Here's your revised plan — you can still make it."
Analytics architecture — end to end
Events to track (every user action becomes a data point)
topic_completed → session_started → session_ended
topic_skipped → reschedule_triggered → streak_broken
revision_due → revision_completed → plan_pace_changed
Each event stores: user_id, plan_id, topic_id, subject_id, timestamp, session_duration_sec, device_type
Velocity score
Topics done / topics planned per day. <0.8 = falling behind. Triggers rescheduler.
Subject health
Per-subject completion %. Red if <50% with <30 days left.
Streak engine
Daily consecutive check-ins. Break = notification + soft reschedule prompt.
Pace projection
At current velocity, will student finish before exam? Updated daily.
Time-of-day pattern
Detect peak study hours. Nudge with "Your best study window is 9–11 PM"
Avoidance detector
Topics skipped 2+ times flagged as "needs attention". Surface to student proactively.

Adaptive planner — how the real-time adjustment works
The core loop (this is what makes it ₹500-worthy)
Student checks in daily → Topics marked done / skipped
System recalculates remaining topics → Checks days left × capacity
Detects gap (backlog) → Auto-redistributes schedule
Shows updated "Today" plan → Student never has to manually re-plan
Reschedule triggers: 3 skipped topics, missed 2 days, velocity < 0.7 for 3 days running, or student manually requests it. Never silently increase daily load past 1.5× the original goal — ask for permission first ("You're 8 topics behind. We can add 2 topics/day or extend your plan by 4 days. Which do you prefer?").
